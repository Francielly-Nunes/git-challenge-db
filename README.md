# Git Challenge: Fluxo Colaborativo e Resolução de Conflitos

Olá! Bem-vindo ao seu desafio de Git, onde você vai praticar o uso de Git em um cenário colaborativo. Aqui, você aprenderá a criar branches, fazer commits seguindo boas práticas, resolver conflitos e integrar suas mudanças através de Pull Requests. Vamos lá?

---

## Objetivo do Desafio

Este desafio tem como foco colocar em prática conceitos essenciais do Git em um ambiente colaborativo. Você irá:

- Criar e gerenciar branches (`main`, `develop`, e branches de funcionalidades)
- Realizar commits com padrões semânticos
- Resolver conflitos de merge
- Trabalhar com Pull Requests para integrar mudanças
- Entender a importância de manter a branch `main` protegida e a branch `develop` como ambiente de integração

---

## O que você precisa fazer

1. **Fork** deste repositório para sua conta no GitHub.
2. Clone o repositório forkado na sua máquina.
3. Atualize suas branches e corrija conflitos entre `develop` e `main`.
4. Crie branches específicas para novas funcionalidades, seguindo uma nomenclatura clara (ex: `feature/minha-nova-funcionalidade`).
5. Faça commits usando o padrão **Conventional Commits**.
6. Atualize o arquivo `comandos-git.md` com comandos Git, baseando-se na branch estável (`main`).
7. Copie o arquivo `comandos-consulta.md` do repositório da atividade prática, renomeando-o para `comandos_consulta_cli.md`.
8. Envie suas mudanças via Pull Request para seu repositório.
9. Aguarde a revisão e aprovação do PR para que suas mudanças sejam integradas ao projeto.

---

## Regras importantes

- **Branches**: Use nomes descritivos e padronizados, como `feature/nova-funcionalidade`.
- **Commits**: Siga o padrão de commits semânticos (ex: `feat: adiciona nova funcionalidade`).
- **Pull Requests**: Descreva claramente as mudanças feitas.
- **Versionamento**: Mantenha o controle de versões e evite commits desnecessários.
- **Terminal**: Faça todas as operações via terminal (Bash, PowerShell, etc.).
- **Conflitos**: Resolva conflitos de merge com atenção, garantindo que os arquivos estejam corretos antes de finalizar.

---

## Dicas úteis

- Use `git pull` frequentemente para manter seu código atualizado.
- Resolva conflitos no terminal, verificando se os arquivos estão corretos antes de concluir o merge.
- Documente bem suas mudanças no PR.
- Preste atenção na nomenclatura de branches e commits para refletir exatamente o que foi alterado.
- Lembre-se de corrigir conflitos em branches de correção e fazer PRs para a branch `develop`, nunca direto na `main`.
